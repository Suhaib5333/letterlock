The whole plan in 13 lines

  1. Wrap, don't rewrite. The React app ships inside a Capacitor shell. One codebase for web, iOS and Android.
  2. Backend leaves Supabase cloud and runs on our VPS. We run the open-source server software ourselves (Postgres, auth, API, realtime). No Supabase account, no bill, no supabase.co anywhere. Only the URL changes in the app. Web and apps share one database. See the "Off Supabase" tab.
  3. That same move fixes the Google login text. The consent screen shows the callback domain. Ours becomes api.letterlock.raltech.dev, then we verify the brand so it reads "Letterlock".
  4. Ads = Google AdMob. Interstitial only between games, rewarded ads for an extra skip or hint, banner only on menus. Never during a question.
  5. Remove Ads = one purchase, about $3.99, through Apple and Google billing via RevenueCat, mirrored to a flag on the account so it follows the login, not just the phone.
  6. Purchases belong to the Apple ID or Google account by default. Our server flag is what makes them follow the user across iPhone, Android and web. The "Remove Ads" tab explains it.
  7. The song, TV-clip and iTunes-melody packs cannot ship in the store build. Apple's guideline 5.2.5 forbids using iTunes previews "as the soundtrack to a game". Replace with self-made public-domain melodies and text clues.
  8. Store requirements we do not have yet: in-app account deletion, privacy policy and terms pages, Sign in with Apple (mandatory because we offer Google login), real PNG icons, offline handling.
  9. "AI-looking code" is a myth. Neither store checks who wrote the code. They reject thin web wrappers, crashes, placeholders and missing privacy features. The "Store review" tab is the real checklist.
  10. Paperwork first: Apple Developer ($99/yr), Google Play ($25 once), AdMob, RevenueCat, and a differentiated store name because exact "Letterlock" is already taken.
  11. Ops we must add: backups, uptime monitoring, crash reporting, a version gate, app-ads.txt.
  12. Realistic money: ads earn tens of dollars a month at hundreds of daily players. The $3.99 purchase will likely out-earn ads early. Do it for reach and polish, not quick revenue.
  13. Mobile and TV are first-class targets. A full mobile experience rehaul (portrait and landscape, no browser bar) built with the frontend-stack pipeline before submission, plus an Android TV / Google TV build controlled with the remote. See the "Mobile & TV" tab.

Mobile experience rehaul, portrait and landscape

6 dev days · frontend-stack▸

Playing on a phone is not great today, and in the browser the URL bar eats the screen in both orientations. This is a full optimization and rehaul of the mobile experience, run through the frontend-stack pipeline before any store screenshot is taken. Details in the "Mobile & TV" section.

  • URL bar: the native app has none; the web version gets an "Add to Home Screen" prompt (full-screen PWA) and a Fullscreen button on Android Chrome; layout never shifts when the bar collapses.
  • Landscape-first host layout: board left at max height, question and host pad right; slim header; thin timer bar. The phone controller locks to portrait.
  • Touch targets at least 44 pt, primary actions in the thumb zone, destructive actions out of the way, type scale re-tuned per breakpoint.
  • Keep the screen awake during a match; audio and motion tuned for low-end Android.
  • Verified with the 17-device no-scroll matrix, before/after screenshots per orientation, and a real iPhone plus a mid-range Android.

Decision D14: Option A or Option B

A · Run the open-source stack ourselves (recommended)

Supabase publishes its server as free open-source software (Postgres + an auth server + a REST layer + a realtime server). We run those containers on our VPS. No account, no bill, no supabase.co, our domain, our disks. ~3 days. The app keeps working unchanged. This is what the plan assumes.

B · Fully custom backend

Write our own API (Node), own login system (email codes, Google, Apple), own websocket server for host + phone rooms, port ~30 database functions. Same end result for users, 4 to 6 extra weeks, more code to maintain. Possible later at any time because the database is plain Postgres in both options.

Either way, "Supabase" as a company disappears from the picture. The only question is whether we reuse their free server software (A) or write our own (B). Wherever this page or the repo doc says "the backend on the VPS", it means Option A unless you pick B.

How do we know who bought Remove Ads?

Short answer: the store account (Apple ID on iPhone, Google account on Android) owns the purchase. Our login does not, unless we copy it there ourselves. We do both.

1Someone taps Remove Ads on an iPhone. Apple charges their Apple ID and records "this Apple ID owns remove_ads". Our account is invisible to Apple and Google.
2Same Apple ID, new phone or reinstall: Restore Purchases re-grants it with no login of ours. Apple requires that button. Android re-grants automatically.
3An iPhone purchase does not appear on Android, and neither appears on the website. Only our server can bridge them.
4Receipts can be faked on a jailbroken phone, so the flag is written only after server-side verification. RevenueCat verifies with Apple or Google and calls our webhook, which sets ads_removed = true on the account in our database.
5iPhone, Android and web all read that one flag when signed in. Ads are hidden if either the store says this device owns it, or the signed-in account has the flag.

Ads: what to know

  • Placement rules are law, not taste. Play forbids interstitials at app open, before a level, mid-action, or on exit. End of a game is the allowed natural break. Rewarded ads are always fine because the user opts in.
  • Consent is mandatory in the EU and UK through Google's own consent SDK, and recommended everywhere.
  • AdMob approval happens after launch. They check app-ads.txt on our domain and the live listing.
  • Money reality. Revenue per 1,000 ad views: interstitial about $10 in the US, $5 in the EU, $1 to $4 in MENA; rewarded $16 to $20 in the US; banners about $1. A party game shows two or three interstitials per half-hour session for a whole room on one device.
