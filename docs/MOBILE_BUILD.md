# Letterlock mobile builds (Capacitor 8)

The iOS and Android apps are the **same web bundle** that deploys to
`letterlock.raltech.dev`, wrapped in a Capacitor shell. `npm run build` writes `dist/`;
`npx cap sync` copies that exact `dist/` into `android/app/src/main/assets/public` and
`ios/App/App/public` and refreshes the native plugin lists. There is no second codebase:
fix it once on the web and the next `cap sync` ships it to both apps.

| Piece | Where |
|---|---|
| Capacitor config | `capacitor.config.ts` (appId `dev.raltech.letterlock`, hostname `letterlock.raltech.dev`, splash / keyboard / status-bar plugin config) |
| Native runtime glue | `src/lib/native.ts` (`initNative()` from `main.tsx`), `src/lib/platform.ts` (`isNative()`) |
| Native CSS polish | end of `src/theme.css`, scoped under `html.is-native` |
| Android project | `android/` (committed; build outputs ignored by `android/.gitignore`) |
| iOS project | `ios/` (committed; Swift Package Manager, no CocoaPods) |
| Icon / splash masters | `resources/` generated by `node scripts/genicons.mjs` from `public/favicon.svg` |
| PWA icons | `public/icons/` (same script) and `public/manifest.webmanifest` |
| Deep-link files | `public/.well-known/apple-app-site-association`, `public/.well-known/assetlinks.json` |
| CI (debug APK, unsigned AAB) | `.github/workflows/android-build.yml` |
| CI (store builds) | `codemagic.yaml` (iOS TestFlight, Android Play internal) |

## Installed Capacitor packages

`@capacitor/core`, `@capacitor/cli`, `@capacitor/android`, `@capacitor/ios`, and the
plugins `@capacitor/app`, `browser`, `haptics`, `share`, `network`, `status-bar`,
`splash-screen`, `keyboard`, `preferences`, `screen-orientation`,
`@capacitor-community/keep-awake`. Dev: `@capacitor/assets`, `sharp`.
Adding a plugin = `npm i @capacitor/<plugin>` then `npx cap sync` (and a store release,
native code changed; OTA cannot ship it).

## What the native shell does (all no-ops on the web)

| Feature | How |
|---|---|
| Deep links `https://letterlock.raltech.dev/join/CODE` | Android App Links intent-filter (`autoVerify`) + iOS Associated Domains. `App.addListener('appUrlOpen')` and `App.getLaunchUrl()` parse the code, `history.replaceState('/join/CODE')` + `popstate` + a `ll:join` CustomEvent for the router. |
| Android back button | Closes the top-most `[role=dialog]` (Escape, then its cancel / scrim), else opens the in-game exit confirm on the board, else leaves the current screen for Home, else `App.minimizeApp()`. |
| Splash | Native splash (dark ground + logo) hidden by `nativeReady()` right after React's first paint. |
| Status bar | Light icons over `#0a0e1f`, not overlaid (safe-area CSS keeps working). |
| Keyboard | `resize: body` so the fixed `100svh` shell shrinks instead of panning. |
| Keep awake | `setMatchActive(true)` while `screen === 'game'` (host reads questions for minutes without touching the screen). |
| Orientation | Portrait lock on `?view=controller` and `/join/*`; unlocked elsewhere (the board follows the device). Manifest `screenOrientation="unspecified"`. |
| Haptics | `haptic()` in `services/audio.ts` calls the Haptics plugin in the apps (iOS WebView ignores `navigator.vibrate`); `navigator.vibrate` is also routed to it. |
| Share | `navigator.share` is routed to the Share plugin, so the Victory share card opens the native sheet. |
| Storage durability | `localStorage` keys `letterlock.*`, `ll_*`, `sb-*` are mirrored into `@capacitor/preferences` on every write and restored at boot if the WebView storage came back empty (iOS can evict it). |
| No pinch-zoom / selection | `user-scalable=no` added to the viewport meta in native only; `html.is-native` CSS sets `user-select: none`, `touch-action: manipulation`, `-webkit-touch-callout: none`, `overscroll-behavior: none` on game surfaces (inputs and the question / answer text stay selectable). |
| Android TV | `LEANBACK_LAUNCHER` intent-filter, `android.software.leanback` and `android.hardware.touchscreen` both `required=false`, 320x180 banner `res/drawable-xhdpi/tv_banner.png`. |

SDK levels: minSdk 24, compileSdk / targetSdk 36 (`android/variables.gradle`). AGP 8.13,
Gradle 8.14, Java 17.

## Placeholders to fill before the store builds

| Placeholder | File | Where to get it |
|---|---|---|
| `TEAMID` (twice) | `public/.well-known/apple-app-site-association` | App Store Connect > Membership > Team ID (10 chars). Then add the Associated Domains capability `applinks:letterlock.raltech.dev` to the App target in Xcode (or via Codemagic's `xcode-project use-profiles` once the App ID has the capability). |
| `TODO:REPLACE...` SHA-256 | `public/.well-known/assetlinks.json` | Play Console > Setup > App signing > **App signing key certificate** SHA-256 (not the upload key). Add a second entry with the debug/upload SHA-256 if you want App Links to verify on sideloaded builds. |
| `APP_STORE_APPLE_ID` | Codemagic env group `letterlock_ios` | App Store Connect > App > General > App Information > Apple ID (numeric). |
| `letterlock_asc` integration | Codemagic UI | App Store Connect API key (Issuer ID, Key ID, .p8), role App Manager. |
| `letterlock_upload` keystore | Codemagic UI > Code signing identities | `keytool -genkeypair -v -keystore letterlock-upload.jks -alias letterlock -keyalg RSA -keysize 2048 -validity 10000`. Keep the .jks and passwords in the RAL vault; Play App Signing holds the real signing key. |
| `GOOGLE_PLAY_SERVICE_ACCOUNT_CREDENTIALS` | Codemagic env group `google_play` | Play Console > Users and permissions > service account with Release manager rights, JSON key. |
| Beta group `RAL team` | `codemagic.yaml` | TestFlight > Internal Testing group name. |

The `.well-known` files must be served with `Content-Type: application/json`, over HTTPS,
without redirects, at the root of `letterlock.raltech.dev`. Vite copies `public/.well-known`
into `dist/.well-known` (verified in `npm run build`); nginx / Cloudflare Pages serve it as-is.

## Build in CI without any local toolchain (the default)

**GitHub Actions, `.github/workflows/android-build.yml`**

```
gh workflow run android-build.yml
# or
git tag app-v1.0.0 && git push --tags
```

Ubuntu runner, Java 17, Android SDK 36, `npm ci`, `npm run build`, `npx cap sync android`,
`./gradlew assembleDebug bundleRelease`. Artifacts: `letterlock-debug-apk`
(`app-debug.apk`, install with `adb install` on a phone or Android TV) and
`letterlock-release-aab` (unsigned, for inspection only). `versionCode` = run number,
`versionName` = the tag without `app-v` (or `0.0.<run>`).

**Codemagic, `codemagic.yaml`** (triggers on `app-v*` tags, or start from the Codemagic UI)

- `ios-testflight`: Xcode 26 on `mac_mini_m2`; `npm ci && npm run build && npx cap sync ios`;
  Swift packages resolved (Capacitor 8 uses SPM, so `pod install` runs only if a Podfile
  ever appears); `xcode-project use-profiles` with the App Store Connect integration;
  build number = latest TestFlight build + 1; `xcode-project build-ipa`; published to
  TestFlight. If a checkout has no `ios/` (a Windows machine cannot run `cap add ios`),
  the workflow runs `npx cap add ios` itself; this repo already commits `ios/`.
- `android-release`: `linux_x2`, Java 17; `npx cap sync android`; `./gradlew bundleRelease`
  signed with the `letterlock_upload` keystore (`android/app/build.gradle` reads
  `CM_KEYSTORE_PATH`, `CM_KEYSTORE_PASSWORD`, `CM_KEY_ALIAS`, `CM_KEY_PASSWORD`); versionCode =
  latest Play build + 1; uploaded to the Play **internal** track as a draft.

## Build locally (a machine with Android Studio / Xcode)

```
npm ci
npm run build             # dist/
npx cap sync              # copies dist/ into android/ and ios/, updates plugins
npx cap open android      # Android Studio: Run on a device / emulator / Android TV emulator
npx cap open ios          # Xcode (macOS only): pick a team, Run
```

Command line: `cd android && ./gradlew assembleDebug` (needs JDK 17 and `ANDROID_HOME`,
or a `local.properties` with `sdk.dir=`). On this Windows workstation there is no Android
SDK, Java or Xcode, so use CI; `npx cap sync android` runs fine here and validates the
project (it is part of the verify checklist).

Live reload against the dev server: add `server: { url: 'http://<your-lan-ip>:5173', cleartext: true }`
to `capacitor.config.ts` temporarily (never commit it; Apple 2.5.2 forbids a `server.url` wrapper).

## Regenerating icons and splash

```
node scripts/genicons.mjs
npx capacitor-assets generate --android --ios \
  --iconBackgroundColor '#0a0e1f' --iconBackgroundColorDark '#0a0e1f' \
  --splashBackgroundColor '#0a0e1f' --splashBackgroundColorDark '#0a0e1f'
```

`genicons.mjs` renders `resources/icon.png` (1024), `icon-foreground.png`, `icon-background.png`,
`splash.png` / `splash-dark.png` (2732), the PWA icons in `public/icons/` and the Android TV
banner from `public/favicon.svg`. `capacitor-assets` fans them out to every Android density,
the adaptive icon layers, and the iOS AppIcon / Splash image sets. After running it, re-check
`android/app/src/main/res/values/ic_launcher_background.xml` is `#0a0e1f` and the
`mipmap-anydpi-v26` background inset is `0%` (the generator rewrites both to its defaults).

## Versioning

One semver for the web bundle (git tag). The native shell version (`versionCode` /
`CFBundleVersion`) only has to move when native code or plugins change; CI derives it from
the store's latest build number so the two never collide. Every app release is built from
the same commit as the web release.

## Testing checklist for a device pass

Audio unlock on first tap, video fullscreen from a TV-clip question, `/join/CODE` link from
WhatsApp opens the app into the controller, Android back on every screen (never a dead end),
airplane mode mid-question shows the offline banner, rotate the board screen (allowed) and the
controller (stays portrait), kill the app mid-match and resume from Home, and on Android TV:
launcher banner present, D-pad reaches every control.
